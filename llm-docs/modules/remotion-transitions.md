## Overview

Plugin-based transition system for Remotion. Each transition is a React component implementing `CustomTransitionProps`. A global registry (`Map`) holds all transitions by ID. Builtin transitions provide standard effects; custom transitions are auto-generated by the upload-transition endpoint on the FFmpeg server.

### init.ts (8 lines)

Side-effect-only module. Imports `./builtin` then `./custom` to populate registry. Must be imported after `registry.ts` evaluates to avoid TDZ errors. Imported by app entry points that need transitions available.

### builtin/index.ts (12 lines)

- `builtin-slide-left`
- `builtin-slide-right`
- `builtin-dip-to-black`

Each builtin exports: default component, `params: TransitionParamSchema`, `meta: TransitionMeta`.

---

### Builtin Transitions (pattern: crossfade.tsx)

All follow same structure:
1. `useCurrentFrame()` + `useVideoConfig()` → compute `progress` (0→1)
2. Render FROM clip with decreasing visibility + TO clip with increasing visibility
3. Use `<OffthreadVideo>` for video, `<Img>` for images, based on `fromAssetType`/`toAssetType`

**crossfade**: Opacity crossfade (FROM opacity 1→0, TO opacity 0→1). No params.
**slide-left**: FROM slides left out, TO slides in from right.
**slide-right**: FROM slides right out, TO slides in from left.
**dip-to-black**: FROM fades to black (first half), black fades to TO (second half).

### custom/index.ts (AUTO-GENERATED, 9 lines)

Generated by FFmpeg server's upload-transition endpoint. Registers:
- `facecamtransitionbox` — has params + meta
- `generate-a-crossfade-remotion-transition-8bcf2f` — no params/meta (bare import)
- `staticfacecam` — has params + meta

## Data Flow

1. App entry imports `transitions/init.ts` (side-effect)
2. All transitions registered in global Map
3. Timeline TransitionEntity + TransitionPropertiesPanel read registry for available transitions
4. TransitionPreview uses `getTransitionEntry()` to get component for rendering
5. FFmpeg server's `render-motion-graphic` / remotion-core pipeline also imports registry for server-side render

## Connections

- [[timeline]] — TransitionEntity uses `getTransitionMeta` for label display
- [[video-preview]] — TransitionPreview uses `getTransitionEntry` for live preview
- [[panels]] — TransitionPropertiesPanel uses `getTransitionParams`, `getRegisteredTransitions`
- [[remotion-core]] — ProjectTimeline renders transitions during export

## Known Issues

- `custom/index.ts` auto-generated — manual edits will be overwritten by next upload
- `generate-a-crossfade-remotion-transition-8bcf2f` registered without params or meta (bare default export only)
- No unregister/hot-reload mechanism — transitions persist for app lifetime
- Registry is `Map` not `WeakMap` — registered component references never garbage collected
