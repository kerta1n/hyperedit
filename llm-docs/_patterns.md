## State Management Pattern

Central hook (`useProject`) owns all mutable state. Components receive data + callbacks as props. No context providers, no Redux, no Zustand.

```text
useProject() → { state, actions } → Home.tsx → child components via props
```

Parallel refs (`tracksRef`, `clipsRef`, `settingsRef`) synced via `useEffect` prevent stale closures in debounced/async operations like `saveProject` and `renderProject`.

## Session Persistence

localStorage key `hyperedit-session` stores session ID. On page load:
1. Check localStorage for existing session
2. Verify server (GET /session/{id}/assets) — if 404, clear and create new
3. All assets/renders stored at `/tmp/hyperedit-ffmpeg/sessions/{id}/`

## Asset Upload Pattern

All assets flow through same pipeline:
1. Frontend uploads via `POST /session/{id}/assets` (multipart)
2. Server auto-generates thumbnails (images: resize, videos: extract frame with timeout)
3. Server returns asset metadata (id, name, type, size, duration, thumbnailUrl, streamUrl)
4. Frontend adds to `assets[]` state

## In-Place Asset Modification

Several operations modify assets in-place rather than creating new ones:
- `process-asset`: Apply FFmpeg command (trim, filter, etc.)
- `edit-animation`: Re-render existing Remotion animation (same asset ID)
- `remove-dead-air`: Replace video file, same path

After in-place modification, frontend calls `refreshAssets()` which appends `?v=Date.now()` cache-buster to streamUrl.

## Streaming Progress (NDJSON)

Long operations stream progress via newline-delimited JSON:
```
{"type":"progress","pct":25,"frames":30,"total":120,"elapsed":"2s"}
{"type":"progress","pct":50,...}
{"type":"result","url":"/session/.../output.mp4"}
```

Frontend reads via `readNDJSONStream()` utility. Content-type must include 'ndjson' or 'stream', otherwise falls back to regular JSON.

## Transition Plugin Architecture

Transitions are React components registered in a global Map:
1. Component implements `CustomTransitionProps` interface
2. Optionally exports `params: TransitionParamSchema` for UI controls
3. Optionally exports `meta: TransitionMeta` for display name
4. Registered via `registerTransition(id, component, params?, meta?)`
5. Side-effect import order: `init.ts` → `builtin/` → `custom/`

Custom transitions auto-generated by FFmpeg server's upload endpoint (writes `custom/index.ts`).

## Two Parallel Transition Systems

| | V1 (Junction) | V2 (Timeline Entity) |
|---|---|---|
| Scope | Between adjacent clips on same track | Independent, any position |
| Storage | `transitions[]` array | `timelineTransitions[]` array |
| Constraint | Only video tracks, clips within 2s | Any track, any timing |
| UI | TransitionIndicator (inline) | TransitionEntity (draggable bar) |
| Component | N/A (builtin only) | References `transitionFileId` from registry |

Both coexist in same project spec. No migration or conflict resolution.

## Caption Flow

1. Upload video → asset on V1
2. Transcribe → Whisper returns word-level timestamps (relative to clip start)
3. Chunk: max 5 words per chunk OR 0.7s pause gap
4. Create caption clips on T1 with `assetId: ''`
5. Caption data stored separately keyed by clip ID
6. Preview: `getPreviewLayers()` converts relative timestamps to absolute
7. Render: ProjectTimeline receives captions in absolute time

## Tab-Aware Operations

```text
if (activeTabId !== 'main') {
  dispatch to updateTabClips(tabId, ...)
} else {
  dispatch to regular clips state
}
```

Each TimelineTab stores its own `clips[]`. All move/resize/delete must check active tab.

## Layer Rendering Order

VideoPreview composites layers by track order:
```
V1 = zIndex 0 (background, full-frame)
V2 = zIndex 1 (overlay, transform applied)
V3 = zIndex 2 (top overlay, default scale 0.2)
T1 = zIndex 10 (captions, DOM overlay)
Transitions = zIndex 50 (Remotion player overlay)
```

## AI-Generated Asset Markers

Assets with `aiGenerated: true` in metadata are deprioritized when selecting context video for new animation generation. Prevents feeding AI output back as context.

## FFmpeg Server Route Matching

Raw Node.js `http.createServer` with regex-based route matching (no Express/Hono). Routes parsed manually from URL pathname. CORS headers added to every response.

## Error Handling

- Frontend: try/catch around fetch calls, errors shown in chat panels
- FFmpeg server: try/catch per request handler, returns `{ error: message }` with appropriate status code
- Streaming: `{"type":"error","message":"..."}` in NDJSON stream
- No global error boundary in React app
